# `dev`: issue files as the source of truth

Module `_internal/dev`. Replaces the nupm `issue` and `tasks` modules and their v3 schema. One v4
`<repo>/docs/issues/<slug>.issue.toml` per issue is the only local store; there is no cache, index
or mirror. This spec covers the schema and the core commands (`dev`, `list`, `query`, `edit`, `new`,
`migrate`). `dev sync` has its own spec.

## Decisions

Recorded as ponytail defaults. D1 to D5 come from the plan; D10 to D14 were recorded on 2026-09-15
while drafting against the 14 shipped files (the audit had seen 9) and are open to veto at this review.

- D1 A v3 task becomes one `[[tasks]]` row with `content = target`, `labels = ["%deliverable"]`,
  `completed = (completed != false)`; each of its subtasks follows as a row with `content = synopsis`,
  `description = "<target>\nllm: <llm>"`, `labels = ["%actionable"]`, `completed = done`. Order:
  deliverable, then its actionables, tasks in numeric key order.
- D2 Migrate refuses shapes it does not map and names the path: `issue.vision.outcome` as a record,
  `issue.vision.landscape.external` as a record, `issue.vision.criteria.language-support`. The two
  files that carry them (`nu-over-bash-hooks`, `polyglot-reference-autodoc-tooling`) are edited by
  hand, then migrated. No generic mapper.
- D3 A slug present in more than one registered repository errors; `--repo <name>` is the only
  disambiguator, on every command that takes a slug.
- D4 `date` is written as the quoted string `"YYYY-MM-DD"`; any value `into datetime` parses is
  accepted on read.
- D5 `dev new --prompt` sends the example file below plus the user's prompt to `claude -p` and expects
  a complete v4 document back; on validation failure the raw reply is saved to a `mktemp` path named
  in the error. `--interactive` uses `input` per header field; `--edit` opens the written file with
  `util editor`.
- D10 `[[issue.landscape]].reference` is optional. A v3 `landscape.internal[]` entry becomes a row
  with `scope = "internal"`, `group = "internal"`; a v3 `landscape.external[]` string becomes a row
  with `scope = "external"`, `group = "external"`, `synopsis = <string>`.
- D11 A v3 `[[issue.bindings.xabort]]` becomes `[[issue.bindings]]` with `kind = "xabort"`,
  `item = action`, `type = trigger.mode` and the optional `conditions = trigger.conditions`. This adds
  one optional key, `conditions: list<string>`, to the bindings row.
- D12 The v3 `tasks.N.id` becomes the deliverable row's `description`.
- D13 A v3 `extends` entry written as a path (`docs/issues/<slug>.issue.toml`) is stored as `<slug>`.
- D14 `dev edit --set` merges into `issue` with `merge deep --strategy=overwrite`: nested records
  merge, lists and scalars are replaced.

## Schema

`version = "4.0.0"`, TOML 1.0 valid, depth at most 3, one shape per key. `dev edit` and `dev new`
build the record in this key order before `to toml`, so every write is canonical:

`version`, then `issue` keys `name slug date status outcome requirements constraints extends output
scope landscape bindings reference`, then `tasks`.

| key | type | required | notes |
|---|---|---|---|
| `version` | string | yes | `"4.0.0"` |
| `issue.name` | string | yes | |
| `issue.slug` | string | yes | equals the file stem |
| `issue.date` | string | yes | written `"YYYY-MM-DD"`, read as datetime (D4) |
| `issue.status` | string | yes | one of `draft`, `open`, `done`, `aborted` |
| `issue.outcome` | string | yes | may be empty |
| `issue.requirements` | list<string> | yes | may be empty |
| `issue.constraints` | list<string> | yes | may be empty |
| `issue.extends` | list<string> | no | slugs |
| `[[issue.output]]` | `path` string, `purpose` string, `alias` string | no | `alias` optional |
| `[[issue.scope.excluded]]` | `item` string, `deferred` string or bool | no | `deferred` optional |
| `[[issue.landscape]]` | `scope` in `internal`/`external`, `group` string, `synopsis` string, `reference` string, `type` string, `incompatibility` string | no | `reference`, `type`, `incompatibility` optional (D10) |
| `[[issue.bindings]]` | `kind` string, `item` string, `type` string, `conditions` list<string> | no | `conditions` optional (D11) |
| `[issue.reference]` | `github = {index int, url string, branch string}`, `todoist = {id string, url string}` | no | tool-owned, written by `dev sync`, never hand-edited |
| `[[tasks]]` | `content` string, `description` string, `labels` list<string>, `completed` bool | no | pointers to Todoist tasks |

Absent optional keys read as an empty list (arrays of tables) or null (`extends`, `reference`,
row-level optionals). Keys with null values are dropped at every level before writing, so a file never
contains `"<Nothing>"`.

Example, `hooks-placement.issue.toml` after `dev migrate` (this file is also what `dev new --prompt`
sends to the model):

```toml
version = "4.0.0"

[issue]
name = "Hooks Placement Decision"
slug = "hooks-placement"
date = "2026-08-21"
status = "aborted"
outcome = "singular"
requirements = ["A definite stance with rationale, recorded where future contributors will find it."]
constraints = [
    "Gates nu-over-bash-hooks; no hook implementation before this freezes.",
    "Decision class is author-owned (manual).",
]

[[issue.output]]
path = "docs/decisions/"
purpose = "Recorded decision: plugin-level hooks.json versus skill-scoped frontmatter."

[[issue.scope.excluded]]
item = "Hook implementation"
deferred = "nu-over-bash-hooks"

[[issue.landscape]]
scope = "internal"
group = "internal"
synopsis = "No hooks shipped yet; placement undecided."
type = "greenfield"

[[issue.bindings]]
kind = "xvalue"
item = "Freezing placement before implementation prevents rework across every future hook the plugin ships."
type = "sequencing-integrity"

[issue.reference.github]
index = 5
url = "https://github.com/zaynram/nu-fluency/issues/5"
branch = "hooks-placement"

[[tasks]]
content = "Placement decision frozen with rationale."
description = "decide-placement"
labels = ["%deliverable"]
completed = false

[[tasks]]
content = "Weigh hooks.json vs frontmatter"
description = """
Placement decision frozen with rationale.
llm: augmentation"""
labels = ["%actionable"]
completed = false

[[tasks]]
content = "Record decision with rationale"
description = """
Placement decision frozen with rationale.
llm: none"""
labels = ["%actionable"]
completed = false
```

## Contracts

```nu
# Load and validate an issue; `--md` renders the GitHub body instead.
export def main [
  slug: string@_slugs
  --repo (-r): string@_repos # Repository to look in when the slug exists in more than one
  --md # Render the issue as the GitHub issue body (Markdown) instead of returning the record
]: nothing -> oneof<record, string>
# dev hooks-placement | get issue.status   # aborted

# Issues across the registered repositories.
export def list [
  --status (-s): string@_statuses
  --repo (-r): string@_repos
]: nothing -> table<slug: string, name: string, status: string, date: datetime, repo: string>
# dev list --status open

# One property of an issue.
export def query [
  slug: string@_slugs
  property: cell-path@_properties
  --repo (-r): string@_repos
]: nothing -> any
# dev query hooks-placement issue.outcome   # singular

# Change an issue and rewrite its file canonically; returns the path.
export def edit [
  slug: string@_slugs
  --repo (-r): string@_repos
  --set: record # Merged into `issue` (D14)
  --add-task: record # A `[[tasks]]` row; `labels` defaults to [] and `completed` to false
  --complete: list<string> # Task contents to mark completed
]: nothing -> path
# dev edit hooks-placement --set {status: open}

# Scaffold a v4 issue file; returns the path.
export def new [
  slug: string
  --repo (-r): string@_repos # Target repository; defaults to the registered repository containing the cwd
  --name (-n): string # Defaults to the slug with dashes as spaces, title-cased
  --interactive (-i) # Ask for name and outcome, then requirements and constraints one per line (empty line ends a list)
  --prompt (-p): string # Draft the document with `claude -p` from the example file and this prompt (D5)
  --edit (-e) # Open the written file with `util editor`
]: nothing -> path
# dev new tri-sync --name "Tri-sync" --edit

# Convert v3 files to v4 in place.
export def migrate [
  ...slugs: string@_slugs
  --all (-a)
  --dry-run (-d) # Report without writing
  --repo (-r): string@_repos
]: nothing -> table<slug: string, from: string, to: string, changed: bool>
# dev migrate --all --dry-run
```

Behaviour:

- Discovery: every row of `$env.repo.path` (`name`, `directory`) contributes
  `<directory>/docs/issues/*.issue.toml`; the slug is the file stem before `.issue.toml`. A slug in
  two repositories errors per D3 unless `--repo` names one.
- `dev` opens the file, checks `version`, the required keys and types above, the `status` enum, that
  `issue.slug` equals the stem, and parses `issue.date` with `into datetime`. The returned record is
  the document with `date` as a datetime.
- `--md` renders, in order: `# <name>` line, the outcome paragraph, `## Requirements` and
  `## Constraints` as bullet lists, `## Output` and `## Landscape` as `to md` tables, `## Bindings`
  as bullets `- <kind>/<type>: <item>`, `## Tasks` as `- [ ]`/`- [x]` lines of `content`. Empty
  sections are omitted.
- `list` returns one row per file, sorted by `date` descending then `slug`; `--status` and `--repo`
  filter.
- `query` is `dev <slug> | get <property>`.
- `edit` applies `--set` (D14), appends `--add-task`, sets `completed = true` for every
  `--complete` content, then rebuilds the record in canonical order, drops null keys, formats `date`
  with `format date %F`, runs `to toml`, saves to `mktemp --tmpdir-path <dir> --suffix .issue.toml`
  in the file's own directory and `mv --force` over the original. Writing an unchanged record
  yields identical bytes.
- `new` writes `version`, `name`, `slug`, `date` (today), `status = "draft"`, `outcome = ""`,
  `requirements = []`, `constraints = []` through the same writer; `--interactive` and `--prompt`
  are exclusive. `--prompt` validates the reply through the same loader before writing.
- `migrate` reads the v3 file, maps every leaf per the table below, refuses on any unmapped or
  D2-listed path, and writes through the same writer. A file already at `4.0.0` returns a row with
  `changed = false`. `--dry-run` returns the same rows without writing.
- No command runs `git`, `gh` or `td`; `--prompt` is the only command that calls `claude`.

## Validation and error copy

| condition | message |
|---|---|
| no registered repository has issue files | `no issue files under docs/issues in the registered repositories; run repo push <dir> to register one or dev new <slug> to create one` |
| unknown slug | `no issue named '<slug>' in the registered repositories; run dev list to see them` |
| slug in several repositories (D3) | `slug '<slug>' found in repos <a>, <b>; pass --repo` |
| `--repo` not registered | `no registered repository named '<repo>'; run repo list to see them` |
| `version = "3.0.0"` | `'<path>' is version 3.0.0; run dev migrate <slug>` |
| other version | `'<path>' is version '<v>'; only "4.0.0" loads and only "3.0.0" migrates` |
| required key missing | `'<path>' is missing <key>; edit <path> then re-run dev <slug>` |
| wrong type | `'<path>': <key> must be <type>, got <type>; edit <path> then re-run dev <slug>` |
| bad status | `'<path>': status must be one of draft, open, done, aborted, got '<x>'; edit <path> then re-run dev <slug>` |
| slug mismatch | `'<path>': issue.slug is '<x>' but the file is named '<stem>'; rename one, then re-run dev <slug>` |
| unparsable date | `'<path>': issue.date '<x>' is not a date; write "YYYY-MM-DD", then re-run dev <slug>` |
| `query` unknown property | `no property <property> in '<slug>'; run dev <slug> to see the record` |
| `edit` without changes | `nothing to edit: pass --set, --add-task or --complete` |
| `--complete` unknown content | `no task '<content>' in '<slug>'; run dev query <slug> tasks to list them` |
| `new` file exists | `'<path>' already exists; run dev edit <slug> or pick another slug` |
| `new` outside a repository | `the cwd is not inside a registered repository; pass --repo` |
| `new` both modes | `pass either --interactive or --prompt` |
| `new --prompt` bad reply | `the reply is not a v4 document (<reason>); raw reply saved to <tmp>; fix it and move it to <path>` |
| `migrate` refused path (D2 or unmapped) | `'<path>': <v3 path> is not mapped by dev migrate; edit <path> then re-run dev migrate <slug>` |
| `migrate` without target | `pass one or more slugs or --all` |

Every message names the file or the next command; none refers to a flag that does not exist.

## Tests

`dev/tests/mod.nu` is the seam (module, `std/assert`, the runner's `skip`); suites live in
`dev/tests/suites/dev.nu` and run with `test dev/tests/suites`. `before each` creates a scratch
repository directory with `docs/issues` and returns its root; each test sets `$env.repo` to that one
row first.

Phase 2 (schema, `dev`, `list`, `query`, `edit`):

- `dev list` on an empty repository returns `[]`.
- A hand-written v4 fixture `alpha.issue.toml` loads: `dev alpha` returns the record, `date` is a
  datetime, `status` validated.
- `dev query alpha issue.outcome` returns the string; an unknown property errors naming `dev alpha`.
- `dev edit alpha --set {status: open}` returns the path and the file re-reads with `status = "open"`;
  `--add-task` appends a row with defaults; `--complete` flips `completed`.
- Editing twice yields identical bytes (`open --raw` compare); the edited file parses under
  `python3 -c 'import tomllib,…'` with exit 0.
- A `version = "3.0.0"` file makes `dev` error with a message containing `dev migrate`; an unknown
  status errors; a slug/stem mismatch errors.
- A second repository row with the same slug makes `dev alpha` error with `--repo`, and `--repo`
  resolves it.
- `dev alpha --md` equals the expected Markdown for the fixture.

Phase 3 (`new`, `migrate`):

- `hooks-placement.issue.toml` copied in: `dev migrate hooks-placement --dry-run` returns
  `changed = true` and leaves the bytes unchanged; without `--dry-run` it rewrites the file, `dev
  hooks-placement` loads, `tomllib` parses it, `tasks` has 3 rows in order (1 deliverable, 2
  actionables), `issue.reference.github.index == 5`, and the file equals the example above.
- `windows-portability-batch.issue.toml` copied in: after migrate, a bindings row has
  `kind = "xabort"`, `type = "OR"` and two `conditions`; the external notes are landscape rows with
  `scope = "external"`; `extends == ["include-dirs"]`.
- `polyglot-reference-autodoc-tooling.issue.toml` copied in: `dev migrate` errors naming
  `issue.vision.outcome`.
- `dev new beta --name Beta` returns a path; `dev beta` loads with `status == "draft"` and today's
  date; `dev new beta` again errors `already exists`; `--interactive` and `--prompt` together error.
- The `--prompt` parse-failure branch is exercised with a stub reply (no model call in tests).
- `dev migrate --all --dry-run` lists every v3 file in the scratch repository.

## Naming

Exported names are `main`, `list`, `query`, `edit`, `new`, `migrate` (and `sync` from the next
spec). A module's exported names are predeclared before its imports are parsed, so an exported
`update`, `rm`, `find`, `get` or `export` would shadow the builtin inside `util`, `todo`, `repo` or
`completion` and break their parse. `edit` and `list` are proven safe (`todo` and `hook` export them
while importing `util`). Run the ide-check after adding every export.
